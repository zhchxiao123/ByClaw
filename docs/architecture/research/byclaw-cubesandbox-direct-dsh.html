Architecture research / Direct DSH

保留 ByClaw 前端，
让会话直接连接 DSH。

把 Chat 的执行和实时输出交回用户私有的 DSH Runtime。ByClaw 继续管理账号、权限、资源和业务数据；CubeSandbox 负责执行隔离与暂停恢复。

建议：每用户一台 Cube原 UI / DSH 原生协议Chat 无 MQ 中转源码结论，未运行验收
可行，但需要替换传输与业务适配。

DSH 已有 RPC、WebSocket、多路会话流、历史快照与序列校验。当前 ByClaw 的消息卡、模型额度、群任务和问答入口仍需衔接。修改一个 WebSocket 地址不足以完成迁移。

完整分析与精确代码位置：设计研究 Markdown · 详细笔记见末尾。

01 / DECISION

一台用户 Runtime，承载多个会话

建议首版

DSH 与工具同一台 Cube

保留当前本机 Bash、文件、browserd UNIX socket、Chromium、桌面与 bycli。多个聊天在同一用户 Runtime 内运行；日常空闲整体暂停。跨用户使用独立 PVM。

后续选项

常驻 DSH + 按需工具 B

仍可不使用 MQ，文本推理不必唤醒工具实例。但现有 Harness 的本机环境、浏览器、文件和进程句柄需要远程适配，迁移面更大。

个人 HARNESS 先落地，OpenClaw / BY_SUPER / 企业共享 Runtime 按后续切片迁移。同一授权安全域的会话共享 OS 用户与文件，cwd 不是隔离边界；跨企业安全域需独立 binding / Runtime，不能混入凭证。

03 / FRONTEND

保留消息卡，替换它们的数据来源

在已有 hooks 下增加 ChatTransport，按会话选择 Legacy 或 DSH。原平台 WS 继续收业务通知。DSH client 复用 /api RPC 与 /api/remote.mux，不引入原生 DSH 页面。

现有能力适配要求
正文、思考DSH preview 与持久输出统一映射；历史与实时使用同一投影规则。
工具调用、diff、附件稳定 toolCallId / session / run；保留卡片、状态和文件权限。
计划、子 Agent、后台任务保留 parent/child 身份与独立终态；后台任务持有 work lease。
审批与用户问答服务端签发 pending action，恢复原卡；不能任意提交 resume ID。
刷新与断线使用 DSH opening snapshot + durable seq；替换 Redis Stream ID 比较。
停止与排队取消当前轮次与清空待执行输入分开；DSH native cancel 默认保留 inbox。

主要接缝：utils/websocket.ts、useSseSender/useSend.ts、chatStream.ts、useChat、service/message.ts、useGlobalChatRuntime.ts。Umi 打包与 client 版本兼容还需最小探针。

04 / HARNESS

复用 DSH，把 Worker 从业务运行时卸下

可信 admission 与 ByClaw 业务 setup

Java 保留 session 权限、模型/额度、资源与附件验证。Harness 保留员工、专家组、群任务、cwd、计划、问答与 byclaw/session-setup。新增专用 byclaw Remote 入口，验证可信上下文后复用 Session/Agent；避免裸 prompt 绕过业务准入。

资源/模型、SessionRuntime、Direct Remote、Legacy Worker 四块组合

ByClawDshCommandHandler 已有 session port，适合拆分。GatewayDataEmitter 换成独立输出端口或共享投影；DSH 直连会话不再使用 Redis Worker 收发，尚未迁移的执行引擎仍走旧路径。

固定镜像版本与 Cube 模板

Harness 默认核心是 dsh-v0.1.5-rc.2，另有模型路由补丁。需要核对实际镜像 digest 和包清单，保持 Node/Python/办公工具、supervisor、UID、UNIX socket、browserd、VNC 与 bycli 契约，再补 Cube envd/模板启动。

Cube Provider 与专用 WS ingress

现有 SandboxRuntimeProvider 没有显式 pause/resume。增加 Cube provider 与生命周期接口，将 runtime provider 配置从 file.storage.type 分离。现有 HTTP ingress 120s timeout 且过滤 Upgrade，需要专用 WS 代理；上游地址只从可信 binding 查询。

05 / LIFECYCLE

看实际工作，决定能不能休眠

页面 presence 与运行 work lease 分开。长推理、后台命令、上传、子 Agent 和待答交互都有独立生命期；浏览器断线只退订。以下按钮演示建议合同，不是运行验收结果。

BUSY推理没有网络流量，也不等于空闲

控制面动作

保留 work lease，等待 Agent / child / tool 真正结束。浏览器心跳不是运行状态来源。

用户可见行为

显示运行中；网络断线可重连，不重发原请求，不暂停或取消 Agent。

首版只 pause/resume，关闭自动 idle DELETE。

热暂停保留同一 PVM 的进程状态；进程重启、删除重建与跨节点恢复是不同合同。旧 A/B 实验只归档工具 B workspace，不能直接作为整台 ByClaw DSH 的恢复方案。

空闲门槛：无 work lease → draining → journal / 产物 flush 与一致 checkpoint → generation + lease 再核对 → Cube pause。新请求取消 drain 或得到明确等待；失联 lease 先调和/fence，不直接按 TTL 删除。现有可见页面每分钟续期和登录自动启动都需调整。

Cube 官方支持 pause/connect。外部 socket 需应用重连；物理资源释放与调度配额不同，恢复可能因容量不足失败。300s 是建议可配置起点，没有本次 ByClaw 压测数据。

06 / DURABILITY

一个运行事实源，持久受理，快照恢复

DSH 是新会话权威

原始日志、受理记录、pending action 与 configVersion 归 Runtime。平台保留 SQL 元数据和可重建投影；旧 SQL 历史继续可读，不伪造为新 DSH 日志。

接纳不等于最后一个 token

现有 native requestId 去重查 inbox / log，但受理入口没有显式 fsync receipt。补 scoped request ledger、digest 与提交状态；相同请求返回原结果，未知副作用不重放。

  • 丢失提交响应先查 requestStatus，禁止换 requestId 盲重发。
  • 重连消费 opening snapshot + 连续 durable seq；临时 preview 不承诺逐 token 补发。
  • Runtime 直接投影到平台；本地持久 outbox + 幂等 HTTP / reconcile，无浏览器也保存终态。
  • 睡眠时从平台投影读列表/完成历史/已发布产物；展示同步水位，最新 workspace 操作才唤醒。
  • Volume 是外部存储引用，clone 不复制卷数据；POSIX、hardlink、SQLite/WAL 与一致备份需专门验证。

Grok 的 SSE 没有 cursor replay，accepted:true 还有非持久降级路径。我们借鉴直连结构，采用 DSH 已有协议并补齐受理合同。

07 / MIDDLEWARE

先移除 DSH Chat 中转，再逐条审计业务依赖

范围改造方向
DSH prompt 与实时输出移除 by-framework Worker / Redis Stream 中转；不部署 NATS 或 Durable Streams。
模型、资源、授权、缓存与锁目前仍用 Redis；可保留，或另迁 BE API / 版本化配置 / DB CAS。
通知、群任务、外部 DOC/ACP/Worker首版保留旧路径并标注；最终全执行链无 MQ 需要 HTTP/MCP/task 接口。
OpenClaw / BY_SUPER / 企业 Node独立路径，个人 HARNESS 成功不能证明这些也完成迁移。
Cube 自身内部 Redis属于沙箱控制面的实现，不是我们新增的 Chat 消息队列。

业务中间件简化应按真实能力逐项推进。直接删除 Redis 服务会影响模型、授权和其他执行器，并不会自动得到完整直连产品。

08 / DELIVERY PLAN

从原页面上的闭环开始验收

00版本、模板与客户端探针

固定实际镜像 digest / 核心包清单，确认 model routing patch；Cube template READY；Umi 最小 native client 打包；auth / HTTP / WS / browserd readiness；展示投影 fixtures。

01个人 HARNESS 原 UI 直连闭环

真实平台账号 → 原前端 → 可信 DSH 入口 → 模型 → Cube 工具/文件。验证文本、思考、工具、刷新、取消、双标签与用户隔离；关闭 DSH Chat Worker 收发仍能完成。包含最小 lease 与持久受理探针。

02自动休眠与恢复

长推理、job、upload跨 idle 不停；无浏览器也记录完成；空闲暂停、同会话恢复文件/浏览器；投影对账、检查点失败、容量不足、pending action 与冷 restart边界明确。

03产品功能与企业权限

模型/额度/Skill、附件/diff、计划/子 Agent/审批、收藏分享、VNC/bycli/connector。资源授权撤销、跨企业、文件路径及过期票据验证。受控模型之后用真实 DeepSeek 复跑。

04扩大无 MQ 与恢复规模

逐个迁移企业、定时入口和外部执行器；之后做进程强杀、PVM 删除恢复、升级回滚与多节点/配额验收。记录延迟、内存、snapshot 成本，不提前承诺 HA 或 exactly-once。

首个场景

登录原页面，选择 HARNESS 员工，提问并写文件；关闭页面仍执行，重开可读完整历史；空闲暂停，同会话唤醒再读文件；另一用户不能读、取消或下载。

SQL 状态/映射等需要真实 migration。实施前确认具体 migration 版本；本轮没有创建 DDL/DML，也没有变更初始化 SQL。
